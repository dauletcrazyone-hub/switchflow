# Прямой перенос телефон ↔ телефон (SwitchFlow Direct v1)

Без компьютера: один телефон показывает QR-код, второй его сканирует — дальше данные идут
напрямую по Wi-Fi. Два Android можно соединить и кабелем Type-C ↔ Type-C.

| Пара | Wi-Fi + QR | Кабель |
|---|---|---|
| Android ↔ Android | ✅ | ✅ (один телефон — USB-хост, второй — аксессуар AOA) |
| Android ↔ iPhone | ✅ | — (iOS не даёт приложениям USB-хост и не бывает аксессуаром Android) |
| iPhone ↔ iPhone | ✅ | — (обмен по кабелю между iPhone доступен только встроенному «Быстрому старту» Apple) |

Приложения переносятся только Android → Android: установочные файлы (base.apk и split-файлы)
без данных внутри; на новом телефоне Android спрашивает подтверждение установки каждого.
iOS не даёт приложениям ни читать список установленных программ, ни устанавливать их.

## Транспорт

- Wi-Fi: TCP. Получатель слушает порт `47830` (если занят — любой свободный) на всех адресах
  IPv4 и показывает QR-код. Отправитель сканирует его и подключается. Обоим телефонам нужна
  одна сеть: роутер или точка доступа, включённая на одном из телефонов.
- Кабель (только Android): телефон, который стал USB-хостом, переводит второй в режим
  USB-аксессуара (AOA, `manufacturer="SwitchFlow" model="SwitchFlow Direct"`), после чего
  bulk-каналы USB — это поток байтов. Запись делится на куски ≤ 16 000 байт, длина куска не кратна
  64 (иначе у передачи нет короткого пакета и читающая сторона ждёт продолжения).
  Подключившийся первым (хост) — «клиент», аксессуар — «сервер».

## QR-код

```
switchflow://direct?v=1&h=192.168.1.5,192.168.43.1&p=47830&k=<43 символа base64url>&n=<имя>&o=android
```

| Параметр | Значение |
|---|---|
| `h` | IPv4-адреса получателя через запятую (до 8) |
| `p` | порт |
| `k` | случайный ключ 32 байта (base64url без `=`), новый при каждом открытии экрана |
| `n` | имя телефона (URL-encoded, до 40 символов) |
| `o` | `android` или `ios` |

## Рукопожатие и шифрование

Открытым текстом:

```
клиент → сервер: "SFD1" · режим (1 байт) · [ключ 32 байта, только режим 2] · nonce клиента 16 байт
сервер → клиент: "SFD1" · nonce сервера 16 байт
```

Режим `1` — ключ из QR-кода (Wi-Fi), `2` — ключ передан в рукопожатии (кабель: физическое
соединение точка-точка заменяет сканирование). Сервер Wi-Fi отклоняет режим 2.

Ключ сессии = HKDF-SHA256(ikm = ключ, salt = nonce клиента ‖ nonce сервера,
info = `"SwitchFlow direct v1"`, 32 байта). Каждая запись:

```
длина шифртекста (u32, big-endian) · AES-256-GCM(шифртекст ‖ тег 16 байт)
nonce GCM = направление (1 байт: 'C' у клиента, 'S' у сервера) · 0 0 0 · счётчик (u64, big-endian)
открытый текст = тип (1 байт) · тело
```

Счётчик у каждой стороны начинается с 0 и растёт на 1; получатель ждёт строго следующий номер,
поэтому запись нельзя повторить или переставить. Неверный ключ — первая же запись не
расшифровывается, соединение закрывается. Максимум записи — 1 МиБ.

## Сообщения

Тело — JSON (UTF-8, camelCase), кроме `DATA`.

| Тип | Кто | Тело |
|---|---|---|
| 1 `HELLO` | оба, клиент первым | `{v, device:{id,name,model,platform,os,app}, intent:"send"\|"receive"\|"any"}` |
| 2 `ROLE` | любой | `{intent:"send"}` — по кабелю: пользователь выбрал на этом телефоне «Отправить» |
| 3 `OFFER` | отправитель | `{sessionId, items:[{k,c,n,s,m?,t?,a?,cnt?,app?}]}` — всё, что будет отправлено |
| 4 `ACCEPT` | получатель | `{ok, skip:[k], freeBytes, error?}` — `skip`: уже есть на телефоне или не подходит |
| 5 `ITEM` | отправитель | `{k}` — начало файла |
| 6 `DATA` | отправитель | байты файла (до 256 КиБ) |
| 7 `END` | отправитель | `{k, size, sha256, error?}`; `error` — исходник не прочитался |
| 8 `ACK` | получатель | `{k, result:"saved"\|"duplicate"\|"failed", error?}` |
| 9 `DONE` | отправитель | `{}` — больше файлов не будет |
| 10 `FINISH` | получатель | `{saved, skipped, failed}` — всё обработано |
| 11 `CANCEL` | любой | `{reason}` |
| 12 `PING` | любой | `{}` — каждые 10 с; нет записей 45 с — связь потеряна |

Поля элемента: `k` ключ, `c` категория (`photos`, `videos`, `music`, `documents`, `contacts`,
`calendars`, `apps`), `n` имя, `s` размер, `m` MIME, `t` дата создания (мс), `a` альбом,
`cnt` число контактов/событий, `app` — `{pkg, label, versionCode, part, parts, minSdk}` для
файлов приложения.

Получатель проверяет SHA-256 полученных байтов, сохраняет файл системными средствами
(MediaStore, Contacts, Calendar, Фото, «Файлы»), перечитывает сохранённое, где это возможно,
и только тогда отвечает `saved`. Файлы приложения складываются во внутреннюю папку и
устанавливаются после переноса через `PackageInstaller` с подтверждением пользователя.

**Обрыв связи.** Отправитель по Wi-Fi переподключается к тем же адресам с тем же ключом в
течение 2 минут и присылает `OFFER` с тем же `sessionId`; получатель пропускает всё, что уже
подтвердил, и недокачанный файл начинается заново.
